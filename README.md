# evogen

> 让 AI 编码助手从自己的会话里学习，把教训沉淀回它的指令文件。

evogen 是一个 monorepo：**内核（kernel）负责「进化」这件事本身的逻辑**，客户端适配器（adapter）负责对接具体宿主。两者通过端口（ports）隔离，内核不依赖任何具体客户端。

第一版只支持 Codex。

---

## 它做什么

```text
会话日志 ─▶ 证据提取 ─▶ 信号归纳 ─▶ 建议生成 ─▶ 自检评分 ─▶ diff 预览 ─▶ 你确认 ─▶ 写入指令文件
   ↑                                                              ↑
 本地读取                                                    默认只追加、可撤销
```

把「每次都要重新纠正助手」变成「助手把纠正记进自己的规则里」。

典型场景：你反复纠正它同类问题、反复补充同一条偏好、某个任务连续失败两次——这些都不该只留在聊天记录里。

## 架构：内核与客户端彻底隔离

| 层 | 职责 | 约束 |
| --- | --- | --- |
| `packages/kernel` | 进化逻辑：证据、信号、建议、评分、应用计划、变更记录 | 纯逻辑。不 import 适配器，不 import `node:fs` / `node:path`，`dependencies` 永远为空 |
| `packages/adapter-*` | 宿主连接器：读会话、枚举可进化面、读写指令文件、算 diff | 只实现内核定义的端口，不反过来调用内核内部 |
| `packages/cli` | 把内核与适配器组装成命令行工具 | 只做参数解析与输出 |

```text
            ┌──────────────────────────────┐
            │           kernel             │
            │  domain  ·  ports  ·  pipeline│
            └───────▲──────────────▲───────┘
                    │ ports        │ ports
            ┌───────┴──────┐  ┌────┴─────────┐
            │ adapter-codex│  │ adapter-*    │
            └───────▲──────┘  └────┬─────────┘
                    └──────┬───────┘
                      ┌────┴────┐
                      │   cli   │
                      └─────────┘
```

目录结构：

```text
packages/
  kernel/          核心逻辑（零依赖、零 IO）
  adapter-codex/   Codex 适配器
  cli/             evogen 命令
docs/
  architecture.md  边界与端口设计
  roadmap.md       里程碑与验收标准
  usage.md         使用文档（CLI 与桌面端完整操作手册）
```

## 供应商中立：为什么这个仓库里不出现任何厂商名

本项目是一个**独立实现**：设计、代码、命名均为原创，问题域来自公开的工程常识（会话驱动地维护 Agent 指令文件），不来自任何特定产品的内部实现。

为了让这一点清晰且可验证，仓库内刻意遵循以下约定：

1. **不出现任何商业产品的名称**，不写「对标 / 兼容 / 参考某某产品」这类表述，也不用它们的功能名命名模块或命令。
2. **不复制、不引用第三方的专有代码与专有文档片段**，贡献里如果带有这类内容，不予合并。
3. **讨论设计来源时只使用通用描述**，例如「会话驱动的指令自进化」。

原因很直接：避免与任何商业产品产生版权、商标或授权上的纠葛，同时保证本项目可以在不依赖任何特定厂商的前提下长期演进。如果将来要对接某个具体宿主，我们对接的是**公开可见的文件格式与接口**（例如宿主自己的会话日志格式），而不是某个产品的内部实现。

## 快速开始

需要 Node.js 24+ 与 pnpm 10+。

```bash
pnpm install
pnpm build
node packages/cli/dist/index.js status
```

`status` 是只读命令，会列出：本机被识别为「可进化面」的指令文件、它们的摘要、以及可读取的会话数量。它不会联网，也不会修改任何文件。

完整的操作手册——包括三段式安全模型、全部 CLI 命令的参数与输出示例、模型配置的三级回退、以及 Evogen Studio 桌面端的各页面说明——见 **[docs/usage.md](docs/usage.md)**。

## Roadmap

每个里程碑都以**可验证的验收标准**结束，细节见 [docs/roadmap.md](docs/roadmap.md)。

| 里程碑 | 目标 | 验收标准 |
| --- | --- | --- |
| **M0 骨架**（已完成） | monorepo、内核与适配器边界、只读命令 | `pnpm build` 通过；`evogen status` 能列出本机可进化面与会话数；`kernel` 的 `dependencies` 为空 |
| **M1 只读闭环**（已完成） | 会话 → 证据 → 建议 → diff 预览（不写盘） | 对 10 个真实会话产出 ≥3 条带出处的建议；`evogen proposals` 输出 diff 且文件未被修改 |
| **M2 写入闭环**（已完成） | 确认后写入、变更记录、精确撤销 | 写入内容包裹在带标记的块里；`evogen revert <change-id>` 能精确删除该块；写入前后摘要可核对 |
| **M4 桌面控制台**（已完成） | 本地桌面面板：仪表盘、建议评审、写入与撤销、变更历史 | Tauri 骨架 + sidecar 跑通；一键发版完成真实发版 v0.0.2 在线验收 |
| **M3 适配器协议** | 第三方只写适配器即可接入新宿主 | 有适配器接口文档与一个最小示例；接入新宿主无需改动内核 |

## 非目标

- 不做云服务，不上传你的会话内容。全部逻辑在本机运行。
- 不默认自动改文件。写入必须经过预览与确认，并且可以精确撤销。
- 不绑定模型或模型厂商，模型调用走可替换的端口。
